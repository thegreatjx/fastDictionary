# 截图 OCR 基准集

这组样本用来拦住「修好一张图，坏掉十张图」。当前仓库只提交生成脚本和清单，不提交生成的 PNG；运行脚本会在指定目录写出图片和 `cases.json`。

## 运行

```bash
python generate_cases.py --out /tmp/fd-ocr-cases
```

脚本只依赖 Pillow。Windows 会优先用 Arial 和 Yu Gothic；找不到字体时退回 Pillow 默认字体，日文样本会标注 `font_fallback`。

## 类别

| 类别 | 覆盖内容 | 为什么必测 |
| --- | --- | --- |
| `dark_banner_ui` | 深底浅字横幅、IDE 提示条、终端截图 | 贴边裁剪和深底最容易让 detector 把首字切成独立框 |
| `hover_word_tiny` | 100% DPI 下 11–14px 单词、窄行短语 | 小字行高低于检测器舒适区 |
| `artistic_and_styled` | 海报艺术字、渐变或阴影标题 | 防止预处理破坏 Indra 原有强项 |
| `multilingual_mixed` | 中英日混排、日文横排 UI、日英混排 | 英语和日语主战场 |
| `low_contrast` | 灰底灰字、禁用按钮、等亮度彩色字 | 灰度反色后文字仍可能消失 |
| `two_color_bg` | 双色或渐变横幅上的文字 | 背景色交界线可能把一行字切开 |
| `vertical_ja` | 竖排日文、游戏/漫画式气泡字 | 通用横排检测器的弱项；如不达标，交给 AI 看图而不是继续堆本地滤波 |
| `negative_non_text` | 纯色块、图标、无字渐变 | 验证误检率和空返回稳定性 |

## 指标

每次改预处理参数或换 OCR 引擎，至少记录：

- `ExactMatchRate`：整图标准化后完全匹配率；
- `CER` / `WER`：英文、日文分别统计；
- `P50` / `P95`：含预处理、复核和压缩的端到端耗时；
- `SuspiciousTriggerRate`：可疑结果触发复核的比例，目标 5%–12%；
- `ManualEditRate`：真实用户改动 OCR 文本框的比例；这是比合成样本更重要的线上信号。

标准化时去掉空白、换行和 `|` 分隔符；不要把模型输出中的 `□`、`U+FFFD` 当噪声删掉，它们要计入错误。
